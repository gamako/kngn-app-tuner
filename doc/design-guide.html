tuner / design guide

Capture the sound.
Light up the center.

Tuner is a chromatic guitar tuner that shares one pitch analyzer across native, CLI, and WebAssembly inputs. This guide follows audio from capture to the needle on screen.

Three layers to remember

INPUT

Capture audio

Microphone, WAV, and generated sine tones are converted into mono f32 sample blocks.

CORE

Detect pitch

pitch.Analyzer uses autocorrelation to produce frequency, note name, cents, and confidence.

VIEW

Show the result

The GUI renders the same result as a note, Hz value, semicircular scale, needle, and status color.

Central design rule: adding an input must not duplicate the analyzer or GUI. Only the input adapter changes; every source converges on the same PCM path.

Data path

The three inputs have different front ends, but share everything after the ring buffer.

Input adapters own the event/real-time boundary. Analysis and drawing run on the application thread.

Input abstraction

NATIVE

src/input_native.zig

Uses kngn's kit.audio.requestCapturePermission() and openCapture(). The audio callback only appends samples to the fixed-capacity ring.

Permission states such as requesting, ready, and denied are exposed to the GUI.

WASM

src/input_web.zig

Receives PCM through a fixed buffer and feeds the same ring used by native input. Browser API orchestration lives in web/tuner.html.

The Wasm boundary is limited to the tuner_capture_* functions.

Pitch analysis

src/pitch.zig converts a recording into a note and its deviation from the target. The following example traces a low E string.

1 / 8192 samples

Fill a window

Input is mono f32 audio. The analyzer keeps an 8192-sample window and advances by 2048 samples at a time.

2 / lag

Find the period

It shifts the waveform and measures how similar it is to the original. The best shift is the period candidate.

3 / cents

Convert to note

The period becomes Hz, the nearest equal-tempered note is selected, and the frequency difference becomes cents.

Autocorrelation finds where the same shape appears again

The analyzer shifts the input by lag samples and sums the products. At a period-sized lag, peaks overlap peaks and valleys overlap valleys, producing a large score. Only lag values corresponding to 60–500Hz are searched.

Why refine the peak?

The true period is not always an integer number of samples. The analyzer uses the three points y0, y1, y2 around the peak to approximate a parabola and adds a fractional correction to best_lag.

refined_lag = best_lag + correction
frequency = sample_rate / refined_lag

Reject unreliable results

RMS is checked first. If rms < 0.008, the result is no_signal. If confidence is below 0.18, or frequency is outside 60–500Hz, the result is unstable.

This prevents silence and noise from being presented as a confident note.

Convert frequency to note and cents

The nearest MIDI note in 12-tone equal temperament is selected, then its target frequency is used as the comparison point. One semitone is 100 cents.

midi_float = 69 + 12 × log2(frequency / 440)
target = 440 × 2^((midi - 69) / 12)
cents = 1200 × log2(frequency / target)

GUI meter design

FLAT0SHARP
VIEW

Utility first, brief accents second

The needle follows with a 0.22 coefficient so input jitter does not become visual jitter.

The center zone is green, nearby segments are amber, and distant ticks are dim. The center glow becomes prominent when the note is in tune.

The drawing uses a small number of lines and rectangles through Context.custom and DrawList. No full-frame loop or real-time work was added.

WebAssembly boundary

Browser microphone permission is asynchronous and cannot be acquired directly inside Wasm. A small ABI connects the browser side and the Wasm side.

1

Request permission

getUserMedia requests a mono input with echo cancellation, noise suppression, and automatic gain control disabled.

2

Collect in a worklet

AudioWorklet and a SharedArrayBuffer ring separate audio processing from the main thread.

3

Submit to Wasm

PCM is copied into the fixed buffer and submitted with tuner_capture_submit before joining the common ring.

tuner_capture_buffer_ptr()
tuner_capture_buffer_len()
tuner_capture_get_state()

Browser requirement: microphone capture does not work from file://. Build the package and serve it with COOP/COEP headers.

Verification

Automated tests and builds

zig build test
zig build gate-web
zig build package-web

These cover pitch detection, the audio ring, input states, and the Wasm package.

Deterministic GUI check

KNGN_HEADLESS=1 \
KNGN_HARNESS_SCRIPT=tests/gui-events.txt \
KNGN_HARNESS_OUT=/tmp/tuner-harness \
zig build run-tuner -- --input tone --frequency 82.4069

A test tone verifies meter centering and deflection without depending on microphone permission.

Checking a real microphone
Run zig build run-tuner; the GUI uses the microphone by default. On macOS, allow access under System Settings → Privacy & Security → Microphone, then play the guitar.
Reproducing a problem from WAV
Use --input file path/to/input.wav in the CLI. This removes microphone timing and permission from the experiment while exercising the same pitch.Analyzer.
